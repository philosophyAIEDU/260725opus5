# 물리 모델과 근사 조건

이 문서는 **엔진이 무엇을 정확히 계산하고, 무엇을 일부러 무시했는지**를 밝힙니다.

근사를 숨기면 학생이 나중에 교과서와 부딪혔을 때 시뮬레이션을 불신하게 됩니다.
그래서 모든 근사에 대해 "왜 그렇게 했고, 언제 그 근사가 깨지는지"를 함께 적었습니다.

---

## 1. 시간 구조

물리 substep 은 **dt = 1/960초 고정**입니다. 어떤 스테이지에서도 바뀌지 않습니다.

화면 프레임 1장에 진행하는 substep 수는 오직 **배속**만으로 정해집니다.

| 배속 | 프레임당 substep |
|---|---|
| 0.1× | 1.6 (정수 분수 8/5로 누산) |
| 0.25× | 4 |
| 0.5× | 8 |
| 1× | 16 |
| 2× | 32 |

**"실제로 흐른 시간"은 물리에 절대 들어가지 않습니다.**
느린 기기에서는 재생이 실시간보다 느려질 뿐, 궤적은 한 치도 달라지지 않습니다.
정확도와 부드러움이 충돌하면 정확도를 택한다는 원칙의 직접적인 적용입니다.

0.1배속의 1.6 substep 같은 값은 부동소수로 누적하면 실행마다 반올림이 달라져
같은 시드인데도 궤적이 갈라집니다. 그래서 분자/분모 **정수쌍**으로 누산합니다.
오차가 원천적으로 0입니다.

시각 `t` 는 `t += dt` 로 누적하지 않고 **정수 substep 수 × dt** 로 매번 다시 계산합니다.
10만 스텝을 넘어가면 누적 덧셈의 반올림이 눈에 보일 만큼 쌓이기 때문입니다.

## 2. 적분기 선택

| 상황 | 적분기 | 이유 |
|---|---|---|
| 보존력만 작용 | 속도 베를레 | 심플렉틱이라 에너지가 진동할 뿐 **한 방향으로 표류하지 않음** |
| 속도 의존 힘(항력·마찰) | 반음적 오일러 + 2회 예측-보정 | 베를레는 `a(p)` 전제. 정상상태(종단속도)를 정확히 수렴시킴 |
| 자기장 속 하전입자 | Boris pusher | 자기력을 **회전**으로 처리해 속력과 자이로반지름을 정확히 보존 |
| (참조용) | RK4 | 4차 정확도지만 심플렉틱이 아님. 기본값으로 쓰지 않음 |

### 왜 에너지 표류가 그렇게 중요한가

롤러코스터·진자 스테이지는 "에너지가 보존된다"를 **눈으로 확인시키는 것**이 목적입니다.
오일러 계열을 쓰면 에너지가 스멀스멀 늘어나서, 학생이 배워야 할 내용을
시뮬레이션이 정면으로 배신합니다. 그래서 이 경우만큼은 적분기 선택이 타협 대상이 아닙니다.

검증 ① — 마찰 없는 진자를 120초(115,200 substep) 돌린 뒤 에너지 드리프트 **2.2 × 10⁻⁶**.

### 왜 Boris pusher 인가

로렌츠력 `F = qv × B` 는 항상 속도에 수직이라 일을 하지 않습니다.
따라서 속력이 보존되어야 하는데, 오일러 계열은 매 스텝 속력을 조금씩 키워
**반지름이 계속 커집니다**. 100주기쯤 돌리면 원이 아니라 나선이 됩니다.

Boris 방식은 자기력 부분을 직교 회전 행렬로 처리하므로 `|v⁻| = |v⁺|` 가
기계정밀도로 성립합니다. 게다가 이산 궤도의 반지름은

```
r = (v·h/2) / tan(θ/2),   θ = 2·arctan(ωh/2)
```

인데 `tan(θ/2) = ωh/2` 이므로 `r = v/ω = mv/(qB)` — **오차 0**입니다.
남는 오차는 회전 주기뿐이고 그 크기는 `(ωh)²/12` 차수입니다.

검증 ⑧ — 반지름 오차 4.3 × 10⁻⁸, 100주기 후 반지름 변화 6.3 × 10⁻⁹, 속력 보존 < 10⁻¹².

**주의:** leapfrog 계열이라 속도는 위치보다 반 스텝 어긋난 시각의 값입니다.
`h = 1/960 s` 에서 표시상 차이는 무시할 수준이고, 속력·반지름 같은 보존량에는 영향이 없습니다.

## 3. 구속 운동 — 호길이 하나로 통일

진자, 경사면, 롤러코스터, 루프는 전부 **"정해진 곡선 위를 움직이는 1자유도 운동"**입니다.
데카르트 좌표에서 구속력을 매 스텝 푸는 대신, 곡선의 **호길이 s** 를 일반화 좌표로 삼으면

```
m·s̈ = F_외력·t̂ + f_마찰
```

이라는 1차원 방정식이 됩니다. 이 방식의 장점:

- 구속이 **정확히** 만족됩니다. 물체가 수치 오차로 트랙을 뚫거나 떨어져 나가는 일이 없습니다.
- 보존력만 있을 때 속도 베를레가 에너지를 장시간 보존합니다.
- 진자와 롤러코스터가 **같은 코드**로 돌아갑니다.

### 법선과 수직항력의 부호 규약

```
n̂ ≡ rot90(t̂) = (−t̂y, t̂x),   곡률 κ 는 dt̂/ds = κ n̂ 로 정의
```

가속도를 프레네 분해하면 `a = u̇ t̂ + u²κ n̂` 이므로

```
N = m u² κ − F_외력·n̂
```

진행 방향 기준 "왼쪽"이 항상 물체가 올라타 있는 쪽이 되도록 트랙을 만들면,
오르막·내리막·루프 안쪽이 **모두 이 규약 하나로 일관됩니다.**
그러면 한쪽 지지 트랙의 이탈 조건이 그냥 **N < 0** 입니다.

| 상황 | 결과 |
|---|---|
| 언덕 마루 (κ < 0) | `N = mg − mu²/R`, `u² > gR` 이면 튀어오름 |
| 루프 꼭대기 (κ > 0, n̂ 이 중심을 향함) | `N = mu²/R − mg`, `u² ≥ gR` 이어야 붙어 있음 |

두 번째 조건에 에너지 보존을 합치면 **출발 높이 h ≥ 2.5R** 이 나옵니다.
검증 ⑦ — 실측 2.5000001 m (이론 2.5 m, 오차 4.1 × 10⁻⁸).

### 한쪽 지지 vs 양쪽 지지

- **한쪽 지지(oneSided)**: `N ≥ 0` 만 가능. N이 음수가 되면 물체가 트랙을 떠나
  자유 낙하로 전환됩니다. 교과서의 "구슬이 루프를 도는" 문제가 이쪽입니다.
- **양쪽 지지(twoSided)**: N의 부호 제한이 없습니다. 강체 막대 진자, 그리고
  **업스톱 휠이 달린 실제 롤러코스터**가 여기 해당합니다.

롤러코스터 스테이지는 양쪽 지지입니다. 실제 코스터 차량은 레일을 아래에서 붙잡는
업스톱 휠 때문에 어떤 속도에서도 레일을 벗어나지 않기 때문입니다.
그래서 루프 통과 조건 `h ≥ 2.5R` 이 "떨어지느냐"가 아니라
**"꼭대기에서 N ≥ 0 을 유지하느냐"** (= 승객이 좌석에서 뜨지 않느냐) 로 나타납니다.
교과서가 실제로 묻는 것이 이 조건입니다.

### 트랙 보간의 근사 조건

높이 프로파일은 **단조 3차 에르미트(Fritsch–Carlson)** 로 보간합니다. C¹ 연속입니다.

자연 3차 스플라인(C²)을 쓰지 않은 이유: 제어점 사이에서 overshoot 해서
**교사가 만들지 않은 봉우리**를 만듭니다. "내가 그린 트랙"과 "시뮬레이션 트랙"이
다르면 그 자체가 오개념을 유발하므로, 곡률 연속성을 포기하고 단조성을 택했습니다.

**그 대가:** 곡률이 제어점에서 불연속이라 수직항력 그래프에 작은 계단이 생깁니다.
실제 코스터는 클로소이드로 곡률을 연속으로 잇습니다.

이 불연속은 실제로 관측 가능한 결과를 냅니다. 급한 내리막 뒤에 완만한 구간이 오면
연결점에서 곡률이 순간적으로 음수가 되어(볼록해져), 빠른 차량이 **한쪽 지지 트랙에서는
그 지점에서 떠오릅니다**. 물리적으로 옳은 거동이지만 코스터 트랙 설계로는 나쁜 모양입니다.

## 4. 마찰

쿨롱 마찰을 씁니다. 정지마찰과 운동마찰을 **분리해서** 구현했습니다.

```
정지: |구동력| ≤ μs·N  이면 움직이지 않음   ← 최댓값이지 항상 그 값이 아님
운동: f = −sign(v)·μk·N                   ← 크기가 정해져 있고 속력과 무관
```

정지마찰이 "필요한 만큼 생기되 상한이 있는 힘"이라는 점은 학생이 가장 자주 틀리는
지점이라, 코드 구조에서도 두 경우를 갈라놓았습니다.

운동마찰이 한 스텝 안에서 속도를 **거꾸로 뒤집는 것은 비물리적**이므로,
부호가 바뀌면 0에서 멈추도록 처리합니다.

검증 ⑤ — 임계각이 `arctan(μs)` 와 기계정밀도로 일치.

### 마찰이 한 일은 반드시 열로 기록됩니다

```
dQ = |f_마찰| · |ds|
```

이걸 빼먹으면 마찰이 있는 계에서 에너지가 **그냥 사라집니다**.
"에너지는 사라지지 않고 형태만 바뀐다"를 가르치는 앱에서 이건 치명적인데,
화면상으로는 아무 증상이 없어 자동 검증이 아니면 잡히지 않습니다.
실제로 개발 중 이 버그가 있었고, 검증 ⑤+ 가 그것을 잡아냈습니다.

**근사:** 스텝 끝의 마찰력으로 한 스텝 전체를 근사합니다(1차 정확).
`h = 1/960 s` 에서 총합 보존 오차는 10⁻¹² 수준입니다.

## 5. 항력

두 가지를 모두 지원합니다.

| 모델 | 식 | 종단속도 | 적용 영역 |
|---|---|---|---|
| 선형(스토크스) | `F = −b v` | `v_t = mg/b` | 저속·소형 (레이놀즈수 ≪ 1) |
| 2차(뉴턴) | `F = −c\|v\|v` | `v_t = √(mg/c)` | 일상 크기·속도 |

낙하 스테이지는 2차 항력을 씁니다. `c = ½ρC_dA` 로, 공기밀도 ρ = 1.225 kg/m³,
구의 항력계수 C_d = 0.47 을 씁니다.

**근사의 한계:** C_d 는 실제로는 레이놀즈수에 따라 변하고, 특히 Re ≈ 3 × 10⁵ 부근에서
급격히 떨어집니다(드래그 위기). 고등학교 범위를 넘고, 이 스테이지의 학습 목표인
"질량이 아니라 공기저항이 원인"에는 영향이 없어 상수로 두었습니다.

검증 ⑥ — 종단속도가 `√(mg/c)` 와 기계정밀도로 일치.

## 6. 충돌 — 연속 충돌 감지(CCD)

**이산 충돌 감지를 쓰지 않습니다.**

"스텝 끝에서 겹쳤는지 본다"는 방식은 빠른 물체가 벽을 통째로 건너뛰면 충돌을
아예 놓칩니다(터널링). dt = 1/960초에서도 500 m/s 물체는 한 스텝에 0.52 m 를
이동하므로 얇은 벽은 그냥 통과해버립니다.

학생이 "속도를 올렸더니 공이 벽을 뚫었다"를 보는 순간 시뮬레이션에 대한 신뢰가
무너집니다. 그건 오개념보다 나쁩니다.

그래서 이렇게 합니다.

1. 스텝 구간 `[0, h]` 안에서 **해석적으로 충돌 시각 t\*** 를 계산
2. t\* 까지만 정상 적분
3. 충격량 적용
4. 남은 `h − t\*` 를 다시 1번부터 반복 (한 스텝 안 다중 충돌 지원)

원-선분은 면 접촉과 두 끝점 접촉을 모두 검사합니다. 끝점을 빼먹으면
벽 모서리를 지나는 물체가 순간이동합니다.

**스윕 근사:** 충돌 시각 계산에는 직선 스윕 `p + v·t` 를 씁니다.
가속도가 만드는 처짐은 `½|a|h²` 이고, `h = 1/960 s`, `|a| ≈ 10 m/s²` 에서
**5 × 10⁻⁶ m** — 물체 반지름의 1/10000 수준이라 접촉 시각에 유의미한 영향이 없습니다.

검증 ⑩ — 500 m/s 물체의 반사 지점을 총 이동거리에서 역산하면 벽면과의 차이가
5 × 10⁻¹⁰ m (재충돌 방지용 여유값의 절반).

### 충격량

```
j = −(1+e)·v_rel,n / (1/m₁ + 1/m₂)
```

같은 크기의 충격량을 서로 반대 방향으로 줍니다.
**운동량 보존이 코드 구조에서 자동으로 따라나오도록** 썼습니다.
질량이 다르면 속도 변화가 다를 뿐 힘(충격량)은 같습니다 —
"무거운 쪽이 더 센 힘을 준다" 오개념의 정면 반박입니다.

에너지 손실은 `½μv²(1−e²)` (μ = 환산질량)로 계산해 열에너지로 옮겨 적습니다.

검증 ④ — 탄성충돌(e=1)에서 운동량·운동에너지·충돌 후 속도 모두 오차 < 10⁻¹².

**지터 억제:** 튀어오르기엔 너무 느린 접근(0.12 m/s 미만)은 놓인 상태로 확정합니다.
이것이 없으면 바닥에 놓인 물체가 매 스텝 미세하게 튑니다.

## 7. 파동 — 유한차분을 쓰지 않는 이유

중첩 원리는 "선형 파동방정식의 해 두 개를 더한 것도 해"라는 **정확한 수학**입니다.

유한차분으로 풀면 수치 분산 때문에 펄스가 진행하면서 모양이 뭉개집니다.
학생은 그걸 "만나서 찌그러졌다"고 잘못 읽고, 이 스테이지가 없애려는 오개념
("두 파동이 만나면 부딪혀 튕긴다")을 오히려 강화합니다.

그래서 각 파동을 d'Alembert 해 `f(x − vt)` 로 **해석적으로** 평가하고 합성파는
단순히 더합니다. 모양 왜곡이 0이므로 "지나간 뒤 원래 모양 그대로"가
화면에서 완벽하게 재현됩니다.

### 경계 반사는 거울상 방법

구간 `[L, R]`, `W = R − L` 에 대해

```
y(x,t) = Σₖ [ f(x + 2kW, t) + s·f(2L − x + 2kW, t) ]
```

`s = −1` 이면 고정단(위상 π 뒤집힘), `s = +1` 이면 자유단입니다.
이 합은 양 끝에서 항들이 정확히 쌍소멸하여 경계조건을 **엄밀히** 만족합니다.

**근사의 한계:** 무한히 이어지는 연속파(사인파)에 반사를 켜면 거울상 합이 유한 항에서
잘리므로 끝부분에 인위적인 흔적이 남습니다. 그래서 정상파는 반사가 아니라
**반대로 진행하는 파원 두 개**로 만듭니다. 정상파의 원리가 그대로 드러나서 교육적으로도 낫습니다.

**모델링하지 않은 것:** 매질의 감쇠, 분산(파장에 따라 속력이 달라지는 현상),
비선형 효과. 고등학교 범위 밖입니다.

## 8. 전기력과 자기력

### 전기력

```
F = qE   (일정한 힘) → a = qE/m (일정한 가속도)
```

중력장 속 포물선 운동과 **수학적으로 완전히 같은 문제**입니다.
유일한 차이는 가속도가 물체의 성질에 의존하는가입니다.

| | 중력 | 전기력 |
|---|---|---|
| 가속도 | `a = g` (질량 무관) | `a = qE/m` (전하-질량비에 의존) |

**근사 조건:** 하전입자에는 중력을 넣지 않았습니다.
실제 전자 편향 실험에서 전기력은 중력보다 10¹³ 배 이상 큽니다.
교과서가 늘 하는 표준 이상화입니다.
대신 비교용 공에는 중력을 **일정한 외력 F = mg 로 명시적으로** 넣어,
두 입자가 각각 어떤 힘 하나만 받는지가 코드에서도 분명히 보이게 했습니다.

### 자기력

```
F = qv × B = q(vy·Bz, −vx·Bz)   (2D, B = (0,0,Bz))
```

힘이 항상 속도에 수직이라 일을 하지 않습니다 → 속력 불변, 등속 원운동.
"힘의 방향으로 물체가 움직인다"는 오개념을 정면으로 반박하는 힘입니다.

적분은 반드시 Boris pusher 로 합니다(위 2절 참조).
`forces.ts` 의 `magneticForce()` 는 자유물체도 표시와 참조 적분기 검증용이며,
Boris 경로에서는 회전 단계가 자기력을 처리하므로 힘 누산에 포함하지 **않습니다**(이중 적용 방지).

## 9. 되감기의 정확도

기록을 두 종류로 나눕니다.

| | 형식 | 용도 | 이유 |
|---|---|---|---|
| 표시용 링버퍼 | Float32, 600프레임(10초) | 타임라인 드래그 | 작고 빠름. 화면과 소수 둘째 자리에 충분 |
| 정확 키프레임 | Float64, 1초 간격 | 되감은 뒤 재개 | 비트 단위 재현이 필요 |

**Float32 상태에서 그대로 재개하면 안 됩니다.** 그 미세한 반올림이 충돌 시각을
바꾸고 이후 궤적을 갈라놓습니다.

그래서 되감기는 이렇게 합니다.

```
가장 가까운 이전 정확 키프레임(Float64)으로 복원
    → 목표 프레임까지 substep 을 다시 밟는다
```

최대 1초분(960 substep)이라 최신 기기에서 1 ms 미만입니다.
결과는 원래 궤적과 **비트 단위로 동일**합니다(determinism.test.ts 에서 검증).

되감은 지점에서 다시 재생하면 그 이후 기록은 새 가지가 됩니다.
물리는 결정론적이라 궤적 자체는 같지만, 배속을 바꿨다면 프레임 경계가 달라지므로
옛 기록을 남겨두면 프레임 ↔ substep 대응이 어긋나기 때문입니다.

## 10. 부동소수점 결정론에 대한 단서

IEEE 754 의 `+ − × ÷ √` 는 규격이 결과를 완전히 규정하므로 어느 엔진에서도 동일합니다.
반면 `Math.sin`, `Math.cos`, `Math.exp`, `Math.pow` 는 **규격이 정확도를 규정하지 않아**
자바스크립트 엔진(V8/SpiderMonkey/JavaScriptCore)마다 마지막 자리가 다를 수 있습니다.

따라서 이 엔진의 결정론 보장 범위는 다음과 같습니다.

- **같은 브라우저·같은 기기 안에서**: 완전한 비트 단위 재현 (되감기·리플레이·교사 시연)
- **다른 브라우저 사이에서**: 삼각함수를 쓰는 경로(원호 트랙, 사인파, 회전)에서
  마지막 자리 차이가 날 수 있음

교실에서 필요한 것은 전자이고, 그것은 보장됩니다.
후자가 필요해지면 삼각함수를 다항식 근사로 직접 구현해야 합니다.

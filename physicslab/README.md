# PhysicsLab: 예측 실험실 — 물리 엔진 + 스테이지 DSL

고등학생용 물리 시뮬레이션 학습 플랫폼의 **계산 계층**입니다.
결정론적 물리 엔진, 스테이지 정의 언어(DSL), 그리고 해석해와 대조하는 자동 검증으로 이루어져 있습니다.

> **이 저장소의 범위**
> 화면(UI·렌더러·워커)은 **포함되어 있지 않습니다.** 아직 완성되지 않아 일부러 뺐습니다.
> 지금 들어 있는 것은 전부 자동 검증을 통과한 부분뿐이고, 화면 없이도
> 명령 한 줄로 물리와 학습 콘텐츠를 끝까지 실행·검증할 수 있습니다.
> 자세한 경계는 아래 [무엇이 들어 있고 무엇이 없는가](#무엇이-들어-있고-무엇이-없는가) 참고.

## 실행 방법

```bash
npm install
npm test
```

두 줄이면 끝입니다. 브라우저도, 서버도, 로그인도 필요 없습니다.

`npm test` 를 돌리면 검증 결과가 표로 출력됩니다.

```
#     검증 항목                    실측              이론              상대오차     허용치
①     진자 120초 에너지 드리프트      1.0280736 J      1.0280746 J      2.153e-6    1.000e-3
②     단진자 주기 (θ₀=5°)          2.0070210 s      2.0060667 s      4.757e-4    2.000e-3
③     포물선 사거리                47.426162 m      47.426163 m      3.135e-8    1.000e-3
...
```

| 명령 | 하는 일 |
|---|---|
| `npm test` | 전체 검증 1회 실행 |
| `npm run test:watch` | 파일을 고칠 때마다 자동 재검증 |
| `npm run typecheck` | 타입 검사만 실행 |

## 이 엔진이 지키는 것

### 1. 정확도가 재미보다 먼저입니다
틀린 시뮬레이션은 오개념을 강화하므로 없느니만 못합니다.
그래서 모든 물리 모델을 **해석해와 대조**해 자동으로 검증합니다.
검증에 실패하면 테스트가 빨간불이 되고, 그 코드는 나가지 않습니다.

| # | 검증 항목 | 허용 오차 | 실제 오차 |
|---|---|---|---|
| ① | 마찰 없는 단진자 120초 에너지 드리프트 | < 0.1 % | 2.2 × 10⁻⁶ |
| ② | 소진폭 단진자 주기 vs 2π√(L/g) | < 0.2 % | 4.8 × 10⁻⁴ |
| ③ | 포물선 사거리 vs v²sin(2θ)/g | < 0.1 % | 3.1 × 10⁻⁸ |
| ④ | 탄성충돌 운동량·운동에너지 보존 | < 10⁻⁹ | < 10⁻¹² |
| ⑤ | 경사면 미끄러짐 임계각 vs arctan(μs) | < 0.01° | < 10⁻¹² |
| ⑤+ | 마찰 포함 에너지 총합 보존 | < 10⁻³ | < 10⁻¹² |
| ⑥ | 2차 항력 종단속도 vs √(mg/c) | < 0.2 % | < 10⁻¹² |
| ⑦ | 루프 통과 최소 높이 vs 2.5R | < 0.5 % | 4.1 × 10⁻⁸ |
| ⑧ | 자기장 속 원운동 반지름 vs mv/qB | < 0.1 % | 4.3 × 10⁻⁸ |
| ⑧ | 100주기 후 반지름 변화 | < 0.1 % | 6.3 × 10⁻⁹ |
| ⑨ | 동일 시드 → 궤적 해시 완전 일치 | 완전 일치 | 일치 |
| ⑩ | 500 m/s 물체의 벽 통과(터널링) | 없어야 함 | 침투 5 × 10⁻¹⁰ m |

②의 4.8 × 10⁻⁴ 은 수치 오차가 아니라 **유한진폭 보정 θ₀²/16** 그 자체입니다(이론값과 일치).

### 2. 같은 조건이면 언제나 같은 결과입니다
되감기, 리플레이, 자동 채점, 교사 시연 재현이 전부 여기에 달려 있습니다.

- `Math.random()` 직접 호출 금지 — 모든 난수는 시드 기반 `rng.ts` 를 경유합니다.
- `Date.now()`, `performance.now()` 같은 실시간 값이 물리 계산에 **한 번도** 들어가지 않습니다.
- 시각은 누적 덧셈이 아니라 **정수 substep 수에서 다시 계산**합니다(부동소수 오차 누적 차단).
- 한 화면 프레임에 substep 을 몇 개씩 묶어 돌리든 결과가 같습니다 → 느린 기기에서
  프레임이 튀어도 궤적이 달라지지 않습니다.

### 3. 물리 루프에서 힙 할당이 0회입니다
벡터 연산은 결과를 받을 `out` 을 인자로 받고, 모든 버퍼는 시작할 때 한 번만 만듭니다.
기록용 링버퍼는 고정 크기 `Float32Array` 이고 `shift()` 를 쓰지 않습니다.

## 물리 모델 요약

| 스테이지 | 겨냥 오개념 | 핵심 모델 |
|---|---|---|
| 낙하의 비밀 | 무거운 물체가 빨리 떨어진다 | 진공 `a = g` vs 2차 항력 `v_t = √(mg/c)` |
| 명중! | 최고점에서는 힘이 0이다 | 등가속도 포물선, `R = v²sin2θ/g` |
| 힘을 밀어라 | 움직이려면 힘이 계속 필요하다 | 뉴턴 제2법칙, 정지/운동마찰 전환 |
| 충돌 실험실 | 무거운 쪽이 더 센 힘을 준다 | 운동량 보존 + 반발계수 |
| 롤러코스터 | 속력이 빠르면 에너지가 늘어난다 | 역학적 에너지 보존, 마찰 → 열, 루프 2.5R |
| 파동의 만남 | 두 파동이 만나면 튕긴다 | d'Alembert 해석해 중첩 |
| 전기장 속 하전입자 | 전기력은 중력과 전혀 다르다 | `a = qE/m` vs `a = g` 궤적 비교 |

적분기 선택 근거, 각 모델의 근사 조건과 그 한계는 [`docs/PHYSICS.md`](docs/PHYSICS.md) 에 정리했습니다.

## 스테이지 추가하기

스테이지는 코드가 아니라 **데이터**입니다. 파일 하나 = 스테이지 하나.
교사가 직접 새 스테이지를 만들 수 있도록 만들었습니다.
따라하는 순서는 [`docs/ADDING_STAGES.md`](docs/ADDING_STAGES.md) 를 보세요.

한 스테이지는 이런 것들로 이루어집니다.

```
겨냥할 오개념  →  학생이 만질 수 있는 변수(단위 포함)
              →  파라미터로부터 초기 세계를 만드는 함수
              →  예측 질문과 그 정답(해석해)
              →  별 3개짜리 미션 3개 (순수 함수 판정)
              →  실행 후 오개념 진단 4지선다 + 되감아 보여줄 결정적 순간
              →  개념 정리 글
```

새 스테이지를 만든 뒤 `npm test` 를 돌리면 자동으로 다음을 검사합니다.

- 미션이 정확히 3개인가, 진단 문항의 정답이 정확히 하나인가
- 모든 슬라이더의 기본값이 범위 안에 있는가
- 그래프가 존재하지 않는 측정 채널을 참조하지 않는가
- 어떤 파라미터 조합에서도 카메라 영역이 뒤집히지 않는가
- 예측 정답이 유한한 값이고 입력 가능 범위 안에 있는가

│  │   ├─ world.ts           step(state, dt) — 결정론적 상태 전이

│      ├─ schema.ts          스테이지 DSL 타입 정의

├─ tests/
│  ├─ analytic.test.ts       해석해 대조 (위 표)
│  ├─ determinism.test.ts    시드 재현성, 프레임 드랍 독립성, 되감기 비트 일치

## 무엇이 들어 있고 무엇이 없는가

**들어 있는 것 (전부 자동 검증 통과)**

- 물리 엔진 전체 — 적분기 4종, 트랙 구속, CCD 충돌, 파동, 되감기 기록
- 재생·되감기·배속을 관리하는 시뮬레이션 드라이버
- 스테이지 DSL 과 스테이지 7개, 그리고 스테이지를 화면 없이 끝까지 돌리는 실행기
- 54개의 자동 검증

**아직 없는 것 (완성되지 않아 뺐습니다)**

- 화면 전체 — 캔버스 렌더러, React UI, 웹 워커, 타임라인 조작
- POER(예측-관찰-되감기-설명) 세션 흐름과 별·배지 저장
- 교사 모드, PWA 오프라인, 단일 HTML 빌드, 다국어

스테이지 정의 안의 `overlays` · `charts` · `decorations` · `fbd` 는 **화면에 무엇을 어떻게
그릴지 선언해 둔 데이터**입니다. 이 값들이 가리키는 측정 채널이 실제로 존재하는지는
지금도 자동 검사하지만, 그것을 그리는 렌더러는 아직 없습니다.
